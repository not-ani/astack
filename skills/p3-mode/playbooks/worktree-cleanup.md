### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` from this skill's directory (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that T3 placed elsewhere (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, push state, and PR state, then suggests a bucket. Pair it with `t3_worktree_list` and `t3_worktree_status`, which name the T3 thread and delegate that own each worktree. Mark any worktree a T3 thread touched in the last four days `verify-recent-thread`.
2. The bucket is advice, not permission. The pinned and active threads are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-thread` row, or anything you doubt, fan delegates out with self-contained briefs to read the threads with `t3_thread_read` and report whether the thread is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, threads are bulk). A pinned thread spawns arena and repro trees into sibling worktrees through `delegate_task` with `isolation: "worktree"`, and those are in use even when their names never hit the sidebar. Pick each delegate's reasoning level and fast or standard speed for the job, per the Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. An `ahead<N>` or `no-remote` branch holds unpushed commits, so name them before you prune. Per Autonomy, clean and merged and not-in-use proceeds. `wip`, unpushed work, and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /`, then re-list with the script and `t3_worktree_list`.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. Enumerate with `device_list`, then `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, and package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which thread, or holding uncommitted or unpushed work).

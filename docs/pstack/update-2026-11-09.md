# pstack update, November 9, 2026

The p3 collection follows Lauren Tan's [pstack at revision 236e5481](https://github.com/cursor/plugins/tree/236e5481d05cbadc315b374a5de54971858c27bb/pstack). The p3 codebase supplies the T3 Code adaptation. All 58 upstream skills are present alongside the local `under-the-hood` skill.

## Skill behavior updated

- `interrogate` now asks adversaries to break the change. A finding survives only when its command reproduces a failure that violates the intent.
- `arena` keeps independent cross-judgment and records missing runners or judges. Configured provider and model choices remain authoritative under T3.
- The router restates the user's goal before acting and carries it into briefs and reports. Delegates choose supported reasoning options for the job while preserving their configured role.
- Autopilot verifies a finished patch with a full swarm once. Later changes receive verification appropriate to their scope. Shipping checks whether a verdict still covers the patch after a rebase and works upward from the lowest unmerged PR.
- Verification skills require a usable launch from empty data, preserve journey preconditions, and identify setup supplied only by a stand-in environment.
- Principles, writing guidance, investigation templates, and orchestration playbooks use current upstream wording where it is independent of the harness.

The seven additions are `create-formal-verification-skill`, `maintain-formal-verification-skill`, `statechart`, `ketchup`, `ketchup-video`, `sharpen`, and `in-your-own-words`.

## T3 Code wiring preserved

Model choices still come from `p3-models.md` and `orchestrator_capabilities`. Explicitly requested providers and models are never replaced without authorization. The existing model configuration is outside synchronization.

Delegation uses T3's supported native or `delegate_task` path. Background completion follows the returned `next` instruction. Child checkout isolation belongs to `delegate_task`. New top-level threads require a user request.

PRs are linked through T3. The parent owns PR watches, and children report state without watching. Scheduled audits remain available for operator-authorized cadences. Thread access uses T3 tools. Secrets use `request_secret`. Browser control and visual presentation follow the T3 runtime's tool rules.

The source PR-watcher implementation and its dependencies are replaced by T3's native PR watch tools. Each omitted source file is recorded in [pstack.lock.json](../../pstack.lock.json).

`p3-help` and `setup-p3` now follow upstream invocation behavior. Help is invoked explicitly. Setup can also be selected from a matching natural-language request.
